# UltraMed Field Ops — working notes for Claude

Kuwait dental-products field-sales PWA (two reps + a supervisor). Everything the
team sees must be true: never report "saved" when it did not land, never show a
figure that cannot be explained on screen.

## Layout
- `www/index.html` — markup and CSS only. The app script is split by area into `www/js/app/01-config.js` … `14-ui-boot.js`, loaded in that order as classic scripts sharing ONE global scope (a function in file 07 may call one in file 12 at run time; only code that runs at load must not reference a later file). Add new code to the file whose area it belongs to (a new file needs its two-line header and a `<script src>` tag in the block, in number order). `APP_REV` (top of `01-config.js`) must match `CACHE` in `www/sw.js`; bump both on every release.
- `scripts/build.js` builds what GitHub Pages publishes (`dist/`, git-ignored): the js/app files are inlined back into ONE `<script>` in index.html, so phones get a single self-contained page exactly as before the split. Never list `js/app` files in the service worker's `SHELL` (the build refuses).
- `www/js/core.js` — pure, unit-tested helpers (dates, ERP parsing, merges, month achievement, the daily e-mail digest). Browser-free; `require`-able from Node.
- `www/js/i18n.js` — the English → Arabic dictionary (exact-string matches).
- Weekly management deck (More → "Weekly management deck", supervisor; v111): `UMCore.weeklyReport` computes the week, `UMCore.weeklyStory` keeps only true achievements and `UMCore.weeklyPages` writes every page's text and figures (all pure, unit-tested); `15-weekly-deck.js` only lays them out with PptxGenJS, loaded on demand from `www/js/vendor/pptxgen.bundle.js` (MIT, vendored — no CDN). Harness: `tests/e2e/weekly-deck.e2e.js`. Order (directors' panel): the week's money on one page (four fixed tiles: the week against last week and the earlier weeks' average, the month against target, new business, the average discount), the closed month on days 1–10, the month's plan (counted to the ERP cut-off: what is left, per working day, the same days of last month, named levers), new business, what sold, price discipline, doctors and clinics, the people (the same rows for everyone), next week, our commitments with "Our ask" (only on the close), then the full appendix (A0 contents … A13 method). Truth rules: an invoice above its discount limit is never a hero, a signature or a cover item; the presenter's own sale never leads the cover; the 8-week page runs only when sales lead; samples are not discount; no score where nothing was measured; brands are net of returns, products as invoiced. Language: English, Arabic or both (two files); the speaker notes are Arabic in both. Arabic uses the team's terms, never a literal translation (مبيعات مفوترة، منتجات تدخل العيادات لأول مرة، حسابات رئيسية، المحقق منذ بداية الشهر …), the team's names in Arabic (مريم، رانوفا، د. غيث), pages, tables and charts mirrored right to left. `wdArBidi` adds the bidi marks LibreOffice and PowerPoint need: RLM after "،" only (never a mark between a letter and "،" or "؛" — it garbles the word), LRM before percentages and digit-led Latin names, a negative written as a word or an operator, an amount kept with its currency by a no-break space; a hyperlink run carries one script only. Design (v110): the Smart Vending look — Calibri, dark green 0B2A1B, Ultramed green 1E7A55, yellow F2B705, light cards EEF4F0; `wdIcon` = the app's own line icons. Company-internal ERP accounts ("Marketing …", "… Advertisement": `UMCore.isInternalAccount`) are never wins, and their zero-value moves are not listed as invoices.
- KPI scorecard (More → "KPI scorecard"; v104): `UMCore.kpiScorecard` scores each person on 10 weighted measures (`KPI_ITEMS`; limits in `BENCHMARKS.kpi`, defaults `KPI_DEFAULTS`, edited in "KPI settings" by the supervisor — `saveBenchmarks` must keep `kpi`). Requests, escalations and stands (More → "Requests, escalations & stands", `16-kpi.js`) are stored in `events` with `kind` and `at` and NO `date`, so the calendar and reports ignore them. Government accounts: `UMCore.isGovClinic` (name pattern, overridden by the Gov chip in Admin → Territory). Plan entries carry `at` (time the clinic was planned) so "plan sent before leaving" can be scored. Harness: `tests/e2e/kpi.e2e.js`.
- Month by month (More → "Month by month", and two slides in the weekly deck; v105): `UMCore.monthlyTrend` — each month's achieved from `monthAchievement` as of its last day, its own DSR target from `UMCore.targetOf` (live target if it belongs to that month, else `targets._history[month]`), day 1–N of every month for a fair comparison with the running month; a month no sales file of that person covers shows "no sales file" (never 0); no KPI for a month with no visit logged.
- Product catalog: the `products` document (seeded once from `PRODUCTS_SEED` for a new account — from the supervisor's phone only, as a compare-and-set that finds no document, v123; an existing catalog never re-seeds). `INTENSIV_PRODUCTS` (01-config.js) holds the Intensiv handpieces and Ortho-Strips with their ERP codes as ids — no prices (v121): each is priced from the sales files (the usual invoiced unit price), or left blank. Products → "Duplicate SKUs / barcodes" (supervisor; `UMCore.productDuplicates`, v121, owner's request): products sharing an item code (`id`) or a barcode (compared as GTINs: digits, leading zeros dropped), listed for review with a copyable report — never merged or deleted. Harness: `tests/e2e/catalog-gaps.e2e.js`.
- ERP account links (v113, supervisor): `erpMap` {ERP customer name: clinicId | '@channel' | '@ignore'} decides which clinic/branch an account's invoices count on. Entry points: clinic card "ERP accounts counted here" (Move… / Count another account here…, incl. "New branch with this name"), the reconciliation audit (تغيير), the Unrecognized list (Link…), the import screen card → `openErpLinks` (every account, `UMCore.erpAccounts`). `erpMapLog` keeps who changed what (best effort, capped). ERP names reach handlers only through data-* attributes and prototype-safe keys. Harnesses: `tests/e2e/erp-links.e2e.js`, `tests/e2e/erp-links-late.e2e.js`.
- Prescriptions given on a visit (v114): a field visit carries `v.rx = [{type, name, qty, doctorId|null}]` — PADS (the owner counts pads; sheets per pad are unknown, never convert) per prescription type for each person met, or the clinic with no one person (null); step 4 "Prescriptions given?" in the visit form, also in Edit visit. Types: `state/rxTypes` {rev, types:[{id, name, active}]} edited by the supervisor (Doctors → Prescriptions → Prescription types) and saved only by compare-and-set on `rev` (`saveRxTypes`; `persist('rxTypes')` is refused); until he saves, the owner's two printed forms are the built-in list (`UMCore.RX_DEFAULT_TYPES`: "Ultramed fast moving products", "Tepe prescription"). Harness: `tests/e2e/visit-rx.e2e.js`.

- Missing clinics, from the daily backups (v116, supervisor): Export → Automatic backups → "Find missing clinics" (`openClinicRecovery`, 13-exports.js; `UMCore.clinicsMissingFromBackups`) compares the live list with every `snap_*` backup: clinics a backup holds and the list does not (newest backup copy, last day seen; deleted in the app — recycle bin / delete log — listed but not ticked), open clinics per person now vs the most any backup had, owners not on the team list. "Bring back the ticked clinics" adds only those (delete log cleared first, recycle-bin copies dropped) and says whether the save landed; visits, tasks and sales files are never touched. The whole-day Restore beside it replaces this month's visits and the tasks — not for a missing clinic; since v121 it refuses a backup of another month (it would have erased this month's visits), says before anything changes how many clinics, tasks and visits it removes, and keeps the sales files (an older index only replaces one with no file at all). v123: it leaves the product catalog as it is, and removes only what is kept somewhere, checked against the cloud as it is now (round 3, re-review 2 and 7; `restoreSnapshotNow`): with no backup yet today, the data as read now is kept first as today's backup (`keptBeforeRestore`; created only if there is still none; measured like the daily backup by `UMCore.snapshotPayload`: above 900 KB without the photo previews; too large or not written → nothing changes). Once today has its backup — the daily one, the copy an earlier restore kept, or today's own backup being restored — a restore NEVER writes it: each document it replaces (clinics, tasks, this month's visits) must be, exactly as the cloud holds it now, in the full backup saved to this device (`_fullBackupSaved.docHash`: the sha256 of each of them as the file holds it; `restoreCover`; only a file handed to the browser counts — round 4: a later read whose sheet was closed without Download had counted as the file on the device, `fullBackupOnDevice`); changed since the file was made → it says which list, asks for a new file and changes nothing (until round 3 any file downloaded within the hour counted, and a second restore wrote over the copy the first had kept). The question says what is removed and where everything it replaces is kept; the lists are read again after the question and written by compare-and-set over exactly that (`persistVisits({ authoritative, expect })` for the visits): a change on another phone in between stops the restore, what it had written is put back and verified document by document, the delete log's revivals are undone (`tombsOf` / `retombMany`), the lists are read again, and the words say whether everything was put back. A write with no answer in time is UNKNOWN, never "unchanged" (round 4: its commit landed after "Nothing was changed" and removed what the restore was stopped for): once the restore stops, a run of its writes writes nothing (`cancelled`, also `persistVisits({ cancelled })`), the document is written as it was all the same (a commit on its way then finds it changed and runs again), and a write that lands late anyway is followed (`storageUpdate(key, fn, ms, onRaw)`) and put back when it does (`restoreFollowLate`); the words say it may still land, and "Nothing was changed" only once that is known (`safety-review.e2e.js` R22, R22b). Still a replace, not an add: what it removes is neither binned nor in the delete log. "Restore from this phone's copy" (the device rows there) compares the copy with the list clinic by clinic (`UMCore.deviceCopyDiff`: not in the list now — deleted ones marked —, fields that differ, doctors only the copy has) and applies only the ticked rows (`applyDeviceCopy`); until v123 it put the old copy back whole. v117/v118 brought clinics back on their own at app start; removed in v119: it downloaded every backup in full on every phone each day (the cloud has no light listing — `storage.list` downloads whole documents) and the cloud showed nothing to bring back.
